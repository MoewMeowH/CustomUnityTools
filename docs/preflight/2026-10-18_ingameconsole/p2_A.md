## 2. 상대 수정안 검토 — 새로 생기는 문제 / 범위 초과 여부

- **A2-17 · B1-01 관련 수정안 — 적용 제외.** `AddOrUpdate`와 명령 병합은 확정 사양에 없는 구조를 추가한다. 게터·값을 함께 보존하는 방식도 값 Watch가 게터를 교체하는지에 관한 의미를 임의로 결정한다. 대안은 메인 전용 검사와 게터 등록 세대 검증이다.

- **A2-18 · B1-02 관련 수정안 — 중간.** 프레임 가드는 초기화·재진입 때 리셋해야 하며, 폴링 가드를 로그 배출까지 무조건 묶으면 필요한 배출을 건너뛸 수 있다. 대응은 폴링 주체와 배출 예산을 구분하는 것이다. 플레이 재진입·일시정지·UI 대체 경로에서 각각 호출 횟수를 검사한다.

- **A2-19 · B1-05 관련 수정안 — 중간.** `finally`에서 `null`을 대입하면 중첩 호출 이전 태그를 잃는다. 이전 값을 저장·복원해야 한다. 스레드 로컬 태그는 사용자 핸들러가 같은 스레드에서 발생시킨 무관한 로그까지 오염시킬 수 있으므로 적용 대상 제한도 필요하다. 중첩·재귀 로그와 지연 처리로 검증한다.

- **A2-20 · B1-08 관련 수정안 — 채택 근거 없음.** 제시된 성공 시 감소 규칙 자체는 주장한 실패 경로를 수정하지 않는다. `while`로 바꾸는 것은 초과분 제거 정책을 바꾸며, 생산이 지속되면 호출 스레드의 작업량도 증가할 수 있다. 실제 결함이 확인되면 짧은 잠금으로 용량·입출력을 함께 관리하는 단순한 bounded queue도 대안이지만, 처리량 영향은 측정해야 한다.

- **A2-21 · B1-07 관련 수정안 — 높음.** 조건은 반드시 `USE_HLOG`로 바꿔야 한다. 공유 빈 컬렉션을 외부에서 변경할 수 있으면 이후 조회까지 오염되므로 반환 타입에 맞는 불변·읽기 전용 구현이 필요하다. 더미 채널은 반환 계약과 공개 프로퍼티 의미를 확인한 뒤 선택해야 한다. **자료 부족: 공개 반환 타입·LogChannel 전체 구현.** 기존 소비 코드 컴파일과 반환값 변경 시도를 검사한다.

- **A2-22 · B1-03·04 및 PF1-03·05 수정안 — 중간.** 닫힌 동안 갱신을 생략한다면 재오픈 시 삭제·Clear·태그·필터까지 복원해야 한다. 행 제거 시 선택 참조·콜백도 해제한다. Watch·태그 지연은 추가 최적화이며, 로그 행 지연 요구와 구분한다. 닫힌 동안 추가→삭제→Clear 후 다시 열어 검증한다.

- **A2-23 · PF1-01·04·06·07 수정안 — 중간.** UI 표시 병합은 가능하지만 코어 이벤트·트리거 검사 생략으로 확장하면 정확성이 바뀐다. 이전 객체와의 동일성 비교만으로 문자열 변환을 생략하면 내부가 변하는 가변 객체를 놓칠 수 있다. 풀은 이전 로그·델리게이트 참조를 지워야 하며, 분할 생성은 생성 중 Clear·링 버퍼 퇴출·닫기를 처리해야 한다. 이러한 최적화는 각각 이벤트 보존·가변 값 표시·수명주기 테스트를 통과한 경우에만 적용한다.

- **A2-24 · 조건부 호출 제거 주장 — 적용 범위 수정.** 로그 메서드의 호출·인자 계산은 호출자에 적용되는 Conditional로 제거하지만, 별도 문장의 `Get` 호출이나 일반 반환값 API의 인자 계산까지 제거되지는 않는다. 기존 생성 파일은 재생성이 필요하다. 심볼 OFF 소비 프로젝트에서 부작용 카운터와 컴파일 결과로 검증한다. 설치 시 심볼 자동 추가는 **범위 밖**이다.

## 3. 내 Phase 1 수정 — 철회·수정한 항목과 이유

- **A2-25 · A1-01 철회.** 워커 Watch와 대기 명령 맵이 사양에서 제거되었다. A1-02는 유지한다. 메인 스레드만 사용해도 게터·이벤트 재진입으로 등록이 무효화될 수 있다.
- **A2-26 · A1-03 수정.** 대기 Watch 맵의 무한 증가 지적은 삭제한다. 고유 태그·채널 증가, 태그 전달 대기량과 처리 예산 문제는 유지한다.
- **A2-27 · A1-04 수정.** 기존 `UNITY_EDITOR || DEVELOPMENT_BUILD` 제안은 폐기하고 `USE_HLOG` 단일 조건으로 교체한다. 심볼 OFF의 우회 UI 생성·수집·평가 차단과 공개 API 호환성 검사는 유지한다.
- **A2-28 · A1-05 일부 철회.** 워커 Clear·설정 변경의 이벤트 전달 문제는 정상 호출 경로에서 발생하지 않아야 한다. 워커 호출 거절과 API별 최초 1회 오류를 검사하는 항목으로 바꾼다. 메인 Clear와 이미 대기 중인 로그의 관계는 미해결이다.
- **A2-29 · A1-06·07·08·09·10·11 유지.** 새 사양이 예외 태그 전달, UI 재바인딩·참조 수명, 창 캐시, 생성 마커, 구독자 예외 경계 문제를 해결하지는 않는다. 실제 구현 결함 확정에는 각 항목의 원본 코드·시험이 필요하다.
- **A2-30 · A1-12 수정.** 대기 Watch 명령 종료 처리는 삭제한다. Shutdown 이후 폴링·로그 배출·재초기화 계약은 유지하며, 테스트 기준은 비개발 빌드가 아니라 심볼 ON/OFF로 바꾼다.
- **A2-31 · 사양 질문 정리.** 활성 조건·출력 Conditional·공개 API 스레드 계약·워커 Watch 병합 질문은 종료한다. 값 Watch와 게터의 관계, 자원 상한, 종료 의미, 자동 생성 1회 범위는 남는다.

## 4. 미해결 쟁점 — 실행이나 사양 결정이 있어야 닫히는 것

- **A2-32 · 높음 — 스레드 검사 초기화.** 최초 호출자가 워커일 때 그 스레드를 메인으로 등록하면 계약이 무너진다. 대응은 확실한 메인 스레드 초기화 지점에서 식별자를 설정하는 것이다. API별 최초 오류 플래그는 동시 호출에서도 한 번만 설정되어야 한다. **자료 부족: 스레드 검사·초기화·오류 출력 코드.** 최초 워커 Get·로그·금지 API 호출을 동시에 실행해 검증한다.
- **A2-33 · 중간 — 심볼 OFF의 위반 진단.** 빈 동작 API와 최초 1회 오류 출력의 우선관계가 명시되지 않았다. 또한 Conditional 호출이 제거된 Watch는 런타임 스레드 검사에 도달하지 않는다. 대응은 비활성 API의 진단 범위와 직접 코어 호출의 동작을 명시하는 것이다.
- **A2-34 · 중간 — 수집·배출·구독 수명.** Shutdown·Clear·정적 리셋과 진행 중인 워커 로그의 관계는 사양 및 구현 확인이 필요하다. 큐를 비우는 것만으로 이후 도착하는 이전 세션 로그까지 차단된다고 보장할 수 없다. 세션 경계 테스트가 필요하다.
- **A2-35 · 중간 — 호환성 및 성능 확정.** **자료 부족: 계획서 원문, 실제 런타임·에디터 코드, 생성 템플릿과 기존 생성 표본, asmdef·package.json, HB_Cheat 소비 코드, 대상 기기·허용 지연.** 본 판정은 제공된 리뷰와 확정 사양의 논리 검토이며, 코드 실행·컴파일·성능 측정은 하지 않았다.
