# 확정 사항 (사용자 답, P1 이후 · P2 전 사전 확정 — P2 뒤 추가 질문은 아래에 덧붙임)

## 원문
> 릴리즈에선 Log 호출 자체를 막을꺼야 그래서 InGameConsole 은 기존 로그를 대체한다는 의미가 있어 물론 직접적으로 Debug.Log 를 호출하면 어쩔수 없고 일단은 HLog 로 호출하는 로그만 conditional 로 막으면 될거같아  워커스레드 watch 는 그렇게 하자 error 같은 형식으로 그냥 못보게 하면 될거같아 최초 파악시 error log 만 노출해주면 될거같아 공개 API 는 전부 메인스레드 전용으로 하고싶긴한대 안되는 부분이 좀 커?

> ㅇㅋㅇㅋ 채널을 가져오는 Get과 출력인 얘들은 지원하자 자체 컨디션은 지금 고민중이긴 한대 커스텀 디파인을 지원할까 말까를 아직도 고민중이야 커스텀 디파인 제거하면 좀더 효율적으로 짤수 있어?

> ㅇㅋ 제거하자. 단 Development 때를 컨디션에 넣지말고 현재 자체적으로 보유하고있는 심볼 있지 않아? 그걸로 onoff 처리하는 방향은 어떄?

> 심볼만으로 제어하는게 난 좋다고 생각이 들긴하는대 왜냐하면 Dev 빌드가 아닌 상황에서 (라이브와 동일한 환경) 로그를 확인해야 되는 경우도 좀 있어서

## 확정
1. **활성 조건 = `UNITY_EDITOR || USE_HLOG`** (계획서 결정 2의 "에디터 + Development Build"를 대체).
   - 심볼 이름은 `USE_HLOG`로 고정. 생성기의 커스텀 Conditional 심볼 설정 제거. 켜고 끄기는 기존 에디터 툴바 버튼(Scripting Define 추가·제거).
   - `DEVELOPMENT_BUILD`는 조건에 쓰지 않는다. 심볼을 켠 빌드는 비개발(라이브와 같은) 빌드에서도 동작하고, 끈 빌드는 개발 빌드여도 동작하지 않는다. 출시 전 심볼 끄기는 빌드하는 사람의 책임(README에 명시). 안전망(`DEVELOPMENT_BUILD` 이중 차단)은 두지 않는다.
   - HLog 로그 메서드 전부(`Log`·`Warning`·`Error`·`Exception`·`LogException`·`LogError`, Watch 계열)를 `[Conditional("UNITY_EDITOR"), Conditional("USE_HLOG")]`로 — 호출과 인자 계산까지 제거. `LogChannel`과 생성 템플릿 모두. 기존 생성 파일은 각 프로젝트에서 재생성 필요.
   - 코어 동작(로그 수집 시작, 콘솔 자동 생성, Watch 평가)도 같은 조건으로 컴파일. 공개 API 시그니처는 유지(조건이 없으면 빈 동작 · 빈 컬렉션 · null 반환).
   - `Debug.Log` 직접 호출은 막지 않는다(범위 밖). 단 콘솔이 켜진 빌드에서는 지금처럼 수집·표시.
2. **스레드 계약**
   - 어느 스레드에서나 허용: 채널 가져오기(`HLog.Get` / `HLog.Channel` / `HLogCore.GetChannel`)와 로그 출력 메서드.
   - 그 밖의 공개 API는 메인 스레드 전용: `Watch` 계열, `Unwatch`, `Clear`, `IsLogEnabled` 설정, `Initialize`, `Shutdown`, `PollWatchGetters`, `FlushPendingLogs`, `InGameConsole`의 UI API.
   - 메인 스레드가 아닌 곳에서 호출되면 처리하지 않고, API별로 처음 한 번만 에러 로그를 출력한다.
   - 이에 따라 계획서의 "키별 최신 명령 대기 맵(PendingWatch)"은 만들지 않는다.
3. 앞선 결정 유지: C(닫힌 콘솔 행 지연 생성 + 코어 링 버퍼), D(README만 실제 코드로), E(자동 생성 1회), Watch는 메인 스레드에서만 상태 변경·평가.

## 추가 확정
> ㅇㅋㅇㅋ EDITOR 디파인도 제거하자 에디터 상에서 프로파일링 할때 조금 힘든경우가 있었어. 이 작업 끝난뒤 패키지 설치시 Define 자동으로 넣게 하는거를 추가해야겠네

- 확정 1을 수정: **활성 조건 = `USE_HLOG`만** (`UNITY_EDITOR` 제외). 심볼이 꺼져 있으면 에디터에서도 HLog 호출·코어 수집·콘솔 자동 생성이 컴파일되지 않는다. 로그 메서드는 `[Conditional("USE_HLOG")]`.
  - 에디터 전용 동작(`BreakIf` · `Assert` · `ReportIf`)은 `[Conditional("USE_HLOG")]`로 호출 여부를 정하고, 몸체는 지금처럼 `#if UNITY_EDITOR`에서만 동작.
  - 에디터 도구(콘솔 창 · 생성기 · 툴바 심볼 버튼)는 에디터 어셈블리라 심볼과 무관하게 존재. 심볼이 꺼져 있으면 창은 "USE_HLOG 꺼짐" 상태를 보여주고 수집 데이터는 비어 있음.
- 범위 밖(후속 작업): 패키지 설치 시 `USE_HLOG`를 Scripting Define에 자동 추가.

## 등록형 조건 감시 (confirmed 9 설계)
> 응 알겠어 에디터 윈도우에서 노출방식은 어떻게 할거야?

> 1번으로 가자

10. `BreakWhen(key, Func<bool>, message, owner, once=true)` · `ReportWhen(key, Func<bool>, reason, owner, once=true)`: Watch 게터 루프에서 프레임당 1회(메인 스레드), 거짓→참 순간에만 발동, once 기본, 에디터는 에러 로그+일시정지(Report는 리포트 파일), 빌드는 에러 로그만, 키는 Watch와 같은 공간(`채널/키`, Unwatch·owner 파괴로 해제), `[Conditional("USE_HLOG")]`, 조건 평가 예외는 에러 1회 후 해제.
11. 에디터 창 노출: Watch Values에만 (값 문자열에 종류·현재값·발동 정보, 발동 시 빨간 강조, `+ Trigger` 대신 Reset). Condition Triggers 서브탭의 별도 영역은 만들지 않음.
