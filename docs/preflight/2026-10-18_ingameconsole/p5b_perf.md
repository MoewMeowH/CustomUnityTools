## 3. 측정 우선순위

1. **모바일 대상 로그 부하:** 메인/워커, 콘솔 닫힘/열림, 상한 도달 전후를 나눠 프레임별 처리량·CPU·GC Alloc·큐 대기를 측정한다. 최초 열기와 이력 전체 교체 후 재개방의 후속 UI 레이아웃 프레임까지 포함한다.
2. **Watch 상시 비용:** UI 없이 불변 값 형식·Unity 객체 게터를 측정한 뒤, 에디터 창·트리거·인게임 Watch 탭을 각각 추가한다. 박싱, 이름 변환, 전체 스냅샷, 개수 문자열, 행 재생성 비용을 구분한다.
3. **생성기 무변경 저장:** 창 닫기·스크립트 리로드 때 파일 재쓰기와 Refresh·임포트·재컴파일 발생 여부를 확인한다. 동일 내용 쓰기 생략으로 후속 작업이 제거되는지 검증한다.

## 4. 성능 관점 결론

**수정 후 진행** — 이벤트별 중복 문자열 할당·Watch 전체 재생성·무변경 생성 파일 쓰기를 줄이고, 남은 메인 로그 무예산 처리와 일괄 UI 생성 비용은 대상 기기에서 검증해야 한다.
